# v3.3.0 - Portfolio Service Transactional Outbox and Idempotent Event Processing

Portfolio Service now applies `trade.executed` events with tenant-scoped idempotency and writes outgoing `portfolio.updated` events through a transactional outbox.

Added:

- Additive `011` Portfolio Service migration for generic processed-event idempotency keys and `portfolio_outbox_events`.
- Stable idempotency key helper using `executionId`, `tradeId`, then `eventId`.
- Same-transaction portfolio mutation, processed-event insert, snapshot creation, and `portfolio.updated` outbox insert.
- Portfolio outbox publisher with `FOR UPDATE SKIP LOCKED`, bounded batches, retries, backoff, terminal failures, and graceful shutdown.
- Internal status endpoints:
  - `GET /internal/portfolio/outbox/status`
  - `GET /internal/portfolio/consumer/status`
- Consumer, idempotency, processing, and outbox Prometheus metrics.
- Tighter `portfolio.updated.v1` schema with tenant, source event/execution, decimal-safe position fields, and correlation ID.
- Local demo script for duplicate-event protection.

Known limitations:

- `portfolio.snapshot.created` remains a database snapshot record in this release; reliable Kafka outbox publication focuses on `portfolio.updated`.
- Kafka publication remains at-least-once, so downstream consumers must be idempotent.
