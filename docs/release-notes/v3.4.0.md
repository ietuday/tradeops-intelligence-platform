# v3.4.0 - Consumer Lag Monitoring, DLQ Visibility, and Autoscaling Signals

v3.4.0 adds operational visibility for event consumers, starting with Portfolio Service and shared metric/status conventions for the rest of the Go consumer services.

## Added

- Portfolio Service `GET /internal/consumers/status` with consumer and DLQ health summary.
- Shared consumer observability types, status classification, bounded Prometheus metrics, and tests.
- Generic consumer lag, processing, DLQ, and outbox metric names for dashboards and alerts.
- Portfolio consumer processing and DLQ metrics wired into the existing retry/DLQ flow.
- Portfolio outbox backlog and publish-error metrics under the generic outbox metric names.
- Compose and Helm configuration for consumer observability thresholds.
- Disabled-by-default Helm consumer autoscaling values and HPA custom metric rendering for consumer lag.
- Prometheus alert rules for high consumer lag, stalled consumers, DLQ messages, old DLQ messages, and outbox backlog.
- Operations docs for consumer lag monitoring, DLQ visibility, and consumer autoscaling.
- Safe local demo script for checking status, Prometheus metrics, and DLQ behavior.

## Metrics

New metric families include:

```text
tradeops_consumer_lag_messages
tradeops_consumer_lag_oldest_age_seconds
tradeops_consumer_last_processed_timestamp_seconds
tradeops_consumer_processing_total
tradeops_consumer_processing_errors_total
tradeops_consumer_rebalances_total
tradeops_dlq_messages
tradeops_dlq_oldest_message_age_seconds
tradeops_dlq_events_total
tradeops_outbox_pending_events
tradeops_outbox_oldest_pending_age_seconds
tradeops_outbox_publish_errors_total
```

Labels stay bounded to service, consumer group, topic, partition, event type, status, and reason.

## Known Limitations

- Portfolio Service is the first fully wired service for the v3.4 status endpoint and generic metrics.
- The initial Portfolio lag view is intentionally safe and in-memory oriented; exact committed-offset versus latest-offset broker-admin collection can be expanded without changing the public metric names.
- DLQ visibility is read-only. Replay and destructive DLQ operations are intentionally out of scope.
