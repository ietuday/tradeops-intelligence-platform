# v3.1.2 - Idempotent Portfolio Trade Execution Processing

## Added

- Portfolio Service consumes `trade.executed` as the authoritative financial mutation source.
- Idempotent processing table keyed by tenant and execution ID, with payload hashes for conflict detection.
- Portfolio transaction ledger with one buyer and one seller row per execution.
- Additive `trade.executed.v1` fields for execution ID, buyer/seller user IDs, currency, and source.
- Portfolio trade processing metrics, duplicate counters, execution lag, and reconciliation failure counters.

## Changed

- `order.filled` is now lifecycle-only for Portfolio Service and no longer mutates cash or holdings.
- Order Service emits the same execution ID that is persisted in `order_executions`.
- Portfolio consumer defaults to `trade.executed`, consumer group `portfolio-service-trade-v1`, and DLQ `portfolio.trade.dlq`.

## Known Limitations

- Fees, tax, settlement timing, margin, short selling, multi-currency FX, and trade corrections are not implemented.
- Existing `portfolio.updated` events are still published directly after commit; a Portfolio Service outbox remains a future reliability improvement.
